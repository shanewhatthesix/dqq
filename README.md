# 🦗 附中·电子斗蛐蛐

纯网页的回合制格斗游戏。把你身边的同学、老师、校领导、网络梗做成"蛐蛐"，
AI 根据描述生成属性和技能，然后两只蛐蛐在竞技场里打一场。

**零成本 · 零硬件 · 不需要服务器 · 不需要构建工具。**

---

## 快速开始

**方法一：直接双击 `index.html`**

对，就这么简单。整个游戏是纯静态的 HTML/CSS/JS，没有构建步骤，不依赖任何外部库和 CDN，
断网也能玩（在线 AI 除外）。所有脚本都用普通 `<script>` 标签加载，没有用 ES Module，
就是为了让 `file://` 直接打开也能跑。

> 小提示：个别浏览器（比如 Safari、或者 Chrome 的无痕模式）在 `file://` 下会禁用
> localStorage，那样改的东西关掉页面就没了。真遇到这种情况，用方法二起个本地服务即可。

**方法二：本地起个小服务**（推荐，行为跟线上一致）

```bash
cd DQQ
python -m http.server 8000
# 然后浏览器打开 http://127.0.0.1:8000
```

## 传到 GitHub 并部署

本地仓库已经建好了（`main` 分支，首次提交完成）。剩下一共两条命令：

```bash
# 1) 登录一次（会打开浏览器，跟着点授权就行，不用手输密码）
gh auth login

# 2) 建仓库并直接推上去（仓库名 dqq 可以改成你想要的）
gh repo create dqq --public --source=. --push
```

没装 `gh` 的话，用纯 git 也行 —— 先去 github.com 网页上新建一个**空仓库**（不要勾 README），然后：

```bash
git remote add origin https://github.com/你的用户名/dqq.git
git push -u origin main
```

### 开启网页访问（GitHub Pages）

推上去之后：

1. 仓库 **Settings → Pages**
2. Source 选 `Deploy from a branch`，分支 `main`，目录 `/ (root)`
3. 等一两分钟，访问 `https://你的用户名.github.io/dqq/`

不需要改任何配置，也没有相对路径问题。仓库里的 `.nojekyll` 是为了让 GitHub Pages
原样发布所有文件（默认的 Jekyll 会吃掉下划线开头的文件和目录）。

### 以后更新代码

```bash
git add -A
git commit -m "改了什么"
git push
```

> 别忘了：改了 `js/` 或 `css/` 要把 `index.html` 里的 `?v=` 加一，
> 否则访客会一直跑缓存的旧版本（详见下面「改完代码要给资源加版本号」）。

## 三种玩法

| 模式 | 说明 |
|---|---|
| **1v1 随机斗蛐蛐** | 两只单挑，全自动战斗 + AI 实时解说。最快最爽，适合录屏发 B 站 |
| **3v3 真人对战** | 同一台设备上两人轮流选招，自由换人，策略性最强 |

对战设置页还有一个 **公平模式**：把双方数值拉到同一稀有度再打，
免得一只传说无脑碾压三只普通。

## 核心机制

### 角色类型（决定类型克制）

🎭 虚构 · 👨‍🏫 导师 · 🏛️ 校领导 · 🎒 同学 · 🌐 网络梗

- 校领导 克制 同学（1.5×）
- 同学 克制 校领导（1.2×）
- 导师 克制 同学（1.2×）
- 校领导 克制 导师（1.2×）
- 虚构和网络梗不吃类型克制

### 攻击属性（6 种）× 防御类型（6 种）

攻击属性：🖍️ 粉笔 · 📚 作业 · 📝 考试 · ⏰ 拖堂 · 🍜 零食 · 📋 规则
防御类型：🎓 学霸 · 😴 学渣 · 👨‍🏫 教师 · 🏃 体育生 · 🎨 艺术生 · 🍳 食堂

每种属性还自带一条被动：

| 属性 | 隐藏特性 |
|---|---|
| 粉笔 | 命中率 +10% |
| 考试 | 暴击率 +20% |
| 规则 | 无视对方 50% 防御 |
| 作业 | 高威力低命中（体现在数值上） |
| 拖堂 | 控制型（体现在技能效果上） |
| 零食 | 回复型（体现在技能效果上） |

防御类型也有被动：**艺术生**额外 8% 闪避，**食堂**每回合回复 4 点 HP。

完整的克制表在游戏内 **设置 → 规则速查** 里可以随时查。

### 伤害公式

```
最终伤害 = 60 × 技能威力÷100 × 属性克制 × 类型克制 × 暴击 × 随机浮动
           × 攻击力 ÷ (攻击力 + 防御力)
```

- 随机浮动 0.85 ~ 1.00
- 考试属性技能暴击率 +20%，暴击倍率 1.5×
- 最低至少 1 点伤害
- **单次伤害不超过目标最大血量的 45%** —— 保证再狠也要三下才倒

最后那一项 `攻击力 ÷ (攻击力 + 防御力)` 是攻防比，攻击力等于防御力时是 0.5。
它保证了 **+30 攻击和 +30 防御对胜负的影响完全一样大**：
攻击 +30 → 伤害 ×1.25；防御 +30 → 受伤 ×1.25。

> 为什么不用「直接减防御点数」或「减伤百分比」？
> 直接减点数：防御低了形同虚设（两下被打死），防御高了弱化攻击直接变成 1 点伤害。
> 减伤百分比（防御÷(防御+K)）：有效血量随防御线性增长，而伤害随攻击线性增长，
> 实测无论 K 怎么调，纯攻击流都能把纯防御流打到 80% 以上胜率 —— 攻击每点永远更值钱。
> 换成攻防比之后，两者才真正对称。

实测节奏（`node tools/simulate.js 3000`）：

| 指标 | 现在 | 改公式前 |
|---|---|---|
| 单击伤害占对方血量（平均） | **17.8%** | 40%+ |
| 单击伤害占对方血量（最大） | **45.6%**（上限 45%） | 无上限 |
| 平均出手几次打死一只 | **6.2 次** | 2.4 次 |
| 一回合内被打死的对局 | **0.0%** | 经常出现 |
| 攻击流 vs 防御流（同样配点） | **51.3% : 48.7%** | 91% : 9% |
| 1v1 平均回合数 | 7.0 | 6.1 |
| 3v3 平均回合数 | 18.3 | 12.5 |

> 注意「几次打死一只」和「几回合结束」要分开看：持续伤害（抄写十遍那类）也在磨血，
> 但不占出手次数。所以「2 次直击 + 3 跳毒毒死」是正常对局，不是被两下秒。
> 真正判断会不会被秒的指标是**单击伤害占比**，它被 45% 的上限卡死。

> ⚠️ **配角色时最容易踩的坑**：每回合只能出一招，所以关键是**主力技能够不够强**
> 以及**属性覆盖面够不够**。把威力平均分给 4 个技能、或者主力全押在粉笔上
> （粉笔打学霸和教师都只有 0.5 倍），战斗力会大打折扣。
> 创建页面会检测这两种情况并提醒你。

## 创建蛐蛐

1. 写名字 + 一句话描述
2. 选角色类型、防御类型、稀有度
3. 点 **🤖 AI 生成属性和技能**（也可以完全手动拖）
4. 随便改，左边改右边实时预览，超模了会拦下来并告诉你哪里超标
5. 存进蛐蛐库

### 稀有度与数值上限

| 稀有度 | HP | 攻击 | 防御 | 速度 | 总属性 | 单技能威力 | 技能总威力 |
|---|---|---|---|---|---|---|---|
| 普通 | 80 | 50 | 50 | 60 | 220 | 40 | 80 |
| 稀有 | 90 | 60 | 60 | 70 | 260 | 50 | 110 |
| 史诗 | 100 | 70 | 70 | 80 | 300 | 60 | 140 |
| 传说 | 110 | 80 | 80 | 90 | 340 | 70 | 170 |

技能 2-4 个，命中率 50%-100%，不允许"一击必杀""无敌"之类的效果。

### 角色立绘（必填）

**每只蛐蛐都必须有自己的立绘**，没传的话存不进蛐蛐库 —— 超模检测里会红字拦下来，保存按钮也是灰的。

创建页「① 这是个什么蛐蛐」里有立绘上传位：

- **上传图片**：手绘、表情包、截图、AI 生成图都行，会自动压缩到 320px
- **用默认立绘**：一键把当前防御类型的字形渲染成一张 PNG（手机上一键就能过，不会被卡住）
- **换一张 / 移除**：随时替换

立绘会出现在：蛐蛐库卡片、对战选人列表、出场顺序、竞技场、以及战报图里。

> ⚠️ **内容安全**：请不要上传真人照片，也不要用指名道姓的真人形象。
> 这条和设计文档「十三、需要想清楚的问题」是一致的 —— 用泛称、不上真人照片。

**为什么是 320px**：立绘存的是 base64，320px 大约 30KB 一张。
512px 要 80KB，十几只蛐蛐再加技能 CG 很容易顶到 localStorage 的 5MB 上限。

**预设角色没有立绘**，它们会退回显示防御类型的字形（圆形的墨线图标），这是有意为之 ——
12 只预设要是都必须有图，新同学一进来就没法开打了。老存档里的角色同理。

### 技能 CG

每个技能可以传一张图。战斗时：

- **传了图** → 全屏展示 CG 1.5 秒，然后结算伤害
- **没传图** → 屏幕震动 + 闪光 + 技能名放大

图片会自动压缩到 640px 再存进浏览器，手绘、表情包、截图、AI 生成图都行。

## AI 生成：离线 / 在线

### 离线生成器（默认，开箱即用）

`js/generator.js` 会分析描述里的关键词，推断属性倾向和技能属性，然后在稀有度上限内配平数值。
**不联网、不花钱、不需要任何配置。**

比如写"拖堂能力极强，粉笔头百发百中"，它会给你高命中的粉笔技能 + 拖堂减益技能。

### 在线大模型（可选，效果更好）

**设置 → 在线 AI** 里填 API Key，支持任何 OpenAI 兼容接口：

| 服务商 | 接口地址 | 推荐模型 |
|---|---|---|
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash`（有免费额度） |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-turbo` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |

### ⚠️ 推理模型会把输出额度吃光

这是最容易踩、也最难自己看出来的坑，单独说：

`deepseek-reasoner`、`deepseek-v4-pro` 这类**推理模型**会先写一大段思维链
（返回 JSON 里叫 `reasoning_content`），**而且思维链也算进 `completion_tokens`**。

实测 `deepseek-v4-pro` 生成一只蛐蛐光思考就要 **1542 个 token**。
如果 `max_tokens` 只给 1200，思考能占满全部额度，答案（`content`）就是**空字符串**：

```
finish_reason    = length      ← 被截断
content 长度      = 0           ← 答案一个字都没有
reasoning 长度    = 1840
reasoning_tokens = 1200        ← 正好等于 max_tokens
```

表现出来就是「接口没有返回内容」，很容易误以为是接口坏了或者提示词有问题。

**处理**：默认 `max_tokens` 已经给到 4096，并且失败会自动降级重试一次（关掉 JSON 模式、
降低温度、把额度翻倍）。想更稳就换 `deepseek-chat` —— 它是非推理模型，1.3 秒返回，不吃思考额度。

### 输出格式的三道保险

1. **JSON 模式**：请求里带 `response_format: {"type":"json_object"}`，由接口层保证返回合法 JSON。
   比在提示词里求它可靠得多。少数接口不认这个参数，会自动降级重试。
2. **提示词约束**：格式要求在最前面和最后面各说一次（首因 + 近因），
   中间夹一个完整的正确样例 —— 只描述结构不给例子，模型很容易自由发挥。
3. **解析容错 + 自动重试**：会剥掉 ```json 代码块、从任意文字里配对括号抠出最外层对象；
   第一次拿不到 JSON 就换个参数再来一次。

设置页有个 **「试生成一只」** 按钮，会完整跑一遍生成流程。它和「测试连接」的区别是：
后者只确认接口通不通，前者能测出「**接口通但拿不到 JSON**」这种最坑的情况。

> ⚠️ **两个重要提醒**
>
> 1. Key 存在你自己浏览器的 localStorage 里。这是纯前端网页，**别在公用电脑上填**，
>    用完记得点"清空 Key"。
> 2. 大模型接口大多**不允许网页直接跨域调用（CORS）**。如果测试连接失败，
>    说明被浏览器拦了——直接用离线生成器就行，效果也够用。

AI 返回的结果不可能是完美的，所以 `js/llm.js` 里的 `sanitize()` 会把数值压回规则内、
补齐缺失字段、裁掉多余技能。**AI 永远不可能生成超模角色**，最多是被自动修正。

## 视觉设计

整个应用是一套**附中文具**：方格纸底纹、钢笔墨蓝、红笔批注、印章、左侧密封线。
再叠江西母题——滕王阁剪影、景德镇青花瓷蓝、香樟绿。

### 配色令牌（改 `css/style.css` 的 `:root` 就能整体换皮）

| 令牌 | 色值 | 用途 |
|---|---|---|
| `--paper` | `#F3EEE2` | 作业本暖白，底色 |
| `--ink` | `#1E3A5F` | 钢笔墨蓝，正文与结构 |
| `--porcelain` | `#2E6489` | 景德镇青花，主强调 |
| `--redpen` | `#C43D2E` | 老师红笔，伤害/暴击/危险 |
| `--gamboge` | `#D9A020` | 荧光笔藤黄，传说/高亮 |
| `--bamboo` | `#4B7A55` | 批改的 √，回复/增益 |

稀有度用**印章**呈现：普通=铅笔灰 / 稀有=青花蓝 / 史诗=朱批红 / 传说=藤黄。

### 字体（全部系统自带，不加载任何外部字体）

- 标题 `KaiTi / 楷体` —— 课本与黑板报的笔意
- 正文 `Microsoft YaHei / PingFang SC`
- 数字 `Consolas / Courier New` —— 成绩单、答题卡的感觉

**不引外部字体是硬约束**：一旦挂了 CDN，双击 `index.html` 离线就跑不起来了。

### 图标

所有界面图标和游戏字形都在 `js/icons.js` 里，是**手写的内联 SVG**
（24×24 线性描边、取 `currentColor`），所以它们会自动跟着纸墨配色走。
原本属性/防御类型用的是 emoji，颜色花花绿绿和纸面打架，现在换成单色笔触字形后整页才统一。

想加图标：往 `js/icons.js` 的 `ICONS` 或 `GLYPHS` 里加一条 path 就行。

### 立绘与字形的双轨

角色形象有两套渲染方式，视觉上等重、可互换：

| | 用在 | 长相 |
|---|---|---|
| **立绘** | 玩家上传/生成的图 | 圆形裁切的照片或插画 |
| **字形** | 预设角色、老存档、没传图的技能 | 单色墨线图标 + 青花圆环 |

`UI.sprite(cricket)` 会自动选：有 `portrait` 用图，没有就返回防御类型的字形。
所以任何地方只要调它，两种形态都能正确显示，布局也不会跳。

### 校徽

左上角和 favicon 用的是**学校官方校徽**，取自附中官网（`jxsdfz.jxnu.edu.cn`）首页头部图，
裁出徽标本体后按纸墨配色重新上色成墨蓝 `#1E3A5F`。

- `assets/logo.png` —— 墨蓝版，给浅色纸面用（界面实际用的就是这张）
- `assets/logo-official.png` —— 官方原色版（白/浅蓝），留给深色背景用

想换成别的版本：**直接用同名文件覆盖 `assets/logo.png` 即可**，不用改代码。
如果要改文件名或路径，改 `js/app.js` 里 `mountBrandIcon()` 的 `img.src`。
万一 `assets/logo.png` 不存在（比如有人拉了代码但没拉图片），界面会自动退回手绘的蛐蛐标记，不会开天窗。

不是猜的。（之前不敢写校训，就是因为没能联网核实。）

想把它用在别处，比如放到页脚或密封线上：

## 怎么改（给后人）

### 加一只预设角色

编辑 `js/data.js` 里的 `PRESET_CRICKETS`，照着现有格式加一条就行，玩家打开就能用。

### 加一堆技能名

`js/data.js` 里的 `SKILL_POOL`，按属性分好组。`power` / `accuracy` 写区间，
生成时会随机取。想加新效果，看下面。

### 加新技能效果类型

1. `js/effect.js`：在 `E.KINDS` 里加一项，`parseText` 里加一条正则，`text()` 和 `shortText()` 里加文案
2. `js/engine.js`：在 `_applyEffect` 的 `switch` 里加一个 `case`
3. `js/commentary.js`：在 `case 'effect'` 里加一句动词

### 加新攻击属性 / 防御类型 / 角色类型

只要在 `js/data.js` 里加，并且把克制表的**每一行都补齐**（少了会按 1× 处理，但表格会不好看）。
然后记得补 `DEFENSE_TYPE_BIAS`（生成器用）和 `SKILL_POOL`。

### 换皮

`css/style.css` 顶部的 `:root` 变量改一改，整个游戏的配色就换了。
每年换一次立绘风格的时候用得上。

### 接后端

现在全部存在 `localStorage`。想改成多人共享蛐蛐库，只要
把 `js/storage.js` 里的几个函数改成 `fetch` 调用，其他代码一行都不用动。

## 平衡性验证

```bash
node tools/simulate.js 3000
```

会做这些事：

- 检查所有预设角色有没有超模
- 跑几千场对战，报告平均回合数、先手胜率、有没有卡死
- 跑一个全角色循环赛，看有没有谁一家独大
- 按稀有度分组内战，检查同级别是否公平
- 边界情况：低攻打高防会不会打不完、无限控制会不会锁死、强制换人次数对不对

改完数值或者引擎，跑一遍这个再说。

## 改完代码要给资源加版本号

`index.html` 里每个 css / js 引用后面都挂着 `?v=1.0.1`：

```html
<script src="js/ui-creator.js?v=1.0.1"></script>
```

**改了 `js/` 或 `css/` 之后一定要把这个号 +1，并同步 `js/data.js` 里的 `DQQ.VERSION`。**

原因：浏览器对静态资源用启发式缓存，GitHub Pages 也不会主动让缓存失效。
不换版本号的话，学生那边会一直跑缓存的旧文件，出现「代码明明改了但没生效」这种
最难查的问题。（我自己在开发时就踩过一次。）

## 已知限制

- **稀有度之间存在碾压**：这是设计使然（传说就是比普通强），跨稀有度对战请开公平模式
- **同稀有度内战也有强弱差**：克制表本身就是石头剪刀布，一个角色能吃死另一个
  （最容易翻车的是把主力全押在粉笔上 —— 打学霸和教师都只有 0.5 倍）。
  创建页面会检查属性覆盖面并提醒你。当前预设的同稀有度胜率区间是 21%~83%
- **改预设数值不会影响已有存档**：`PRESET_CRICKETS` 只在蛐蛐库为空时灌一次，
  之后玩家库里存的是自己的副本。后人改了预设数值，老玩家需要手动删掉重加，
  或者在「设置 → 恢复预设角色」里补回来
- **战斗上限 30 回合**：超过就按剩余血量比例判定，避免僵持局
- **localStorage 容量约 5MB**：CG 图片占大头，存不下时会提示你删几只带图的
- **浏览器直连大模型可能被 CORS 拦截**：这是浏览器安全策略，不是 bug，用离线生成器即可
- **3v3 是同一台设备轮流操作**，还没做联网对战

## 内容安全

- 角色用泛称，**不要指名道姓真实的人**，不要上传真人照片
- 在线 AI 的提示词里已经写了"不要设计人身攻击、侮辱性内容"，但 AI 不一定百分百听话，
  **存进蛐蛐库前请自己过一眼**
- 所有数据只存在玩家自己的浏览器里，不上传任何服务器
